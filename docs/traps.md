### Календар: `cost_fact` — лише додаткові витрати, не компенсація (інакше ROI задвоєно)
**Симптом:** 22.10.2026 техчерговий подав у календар `cost_fact` = посткомпенсацію з файлу Альони для PetHouse, MasterZoo, Є-ЗОО.
**Причина:** `analysePromo` (dashboard/marketing/lib/econ.js) рахує `contribution = incGP − cost_fact − compCost`, де `compCost` = фактична компенсація з `moysklad_payments_out` («компенсація … / посткомпенсація», 75 днів після акції) або `comp_pct × виручка`. Компенсація в `cost_fact` віднімається вдруге.
**Роби:** у `cost_fact` лише витрати понад знижку (реклама, POS, зразки); компенсацію не вносити руками. Запит #20261022-1243-faa2 подано вже без неї; правило в CLAUDE.md бота.
**Бачено:** 22.10.2026

### МойСклад: GET документа за id віддає і видалені (кошик), список їх не віддає
**Симптом:** 21.10.2026 звірка видалених прибрала з D1 відвантаження 82878c2f…, а `GET /entity/demand/<id>` повернув 200, ніби документ живий.
**Причина:** видалений документ лежить у кошику МойСкладу: GET за id віддає його з полем `deleted` (тут 15.10.2026), а списки (`/entity/demand?…`, фільтр `id=`) його не містять. Звірка порівнює зі списком, тому відпрацювала правильно.
**Роби:** перевіряючи «чи документ живий», дивись поле `deleted` у відповіді, а не лише код 200/404.
**Бачено:** 21.10.2026

### Повна дозавантажка однією сутністю за прогін блокує звичайний синк
**Симптом:** 21.10.2026 з 17:01 до 22:02 UTC відвантаження не синкались зовсім: прапорець `__backfill` (updated>=2025-01-01, лише demand) щогодини падав на 503 МойСкладу і «D1_ERROR: Network connection lost», а звичайний крок demand у цьому режимі не виконувався.
**Причина:** 2 576 документів по 25 на сторінку з розгорнутими позиціями за один прогін: МойСклад і D1 не витримують, а прапорець не знімається, поки є помилки.
**Роби:** для важких сутностей лише `__window` (до 3 місяців за прогін, після звичайних кроків, успішні місяці знімаються). `__backfill` лишати для легких (оплати, повернення, закупівлі). Ліміт CPU воркера підняли до 300 с.
**Бачено:** 21.10.2026

### Синк `barpi-sync` за `moment>` губив документи заднім числом і зміни сум
**Симптом:** 21.10.2026 оплат у D1 менше, ніж у МойСкладі: червень −1, липень −1, вересень −2 (−54 723 грн), жовтень −2 (−416 726 грн); у серпні кількість та сама, а сума на 46 550 грн інша. Ці документи не з'являлись ніколи, бо курсор уже пішов далі.
**Причина:** усі документні синки (`syncTransactionalEntity`, supply, loss, processing) брали `moment > останній moment`. Документ, проведений заднім числом, або змінений після синку, під фільтр не потрапляє.
**Роби:** з v1.7 фільтр `updated >= остання успішна синхронізація − 1 год` (`sinceFilterFor`, час МойСкладу UTC+3). Пропущене раніше дозавантажується рядком `sync_state(entity='__backfill', last_moment='YYYY-MM-DD|сутності')`: найближчий прогін підхоплює його і видаляє. Видалені в МойСкладі документи досі лишаються в D1. Цифри звіряй з API МойСкладу, а не з D1 (`AGENTS.md`).
**Бачено:** 21.10.2026

### Назви секретів у GitHub ≠ назви в коді й `.env`
**Симптом:** воркфлоу проходить зелений або падає з порожньою змінною; `curl` до Cloudflare повертає 400/403, хоча «токен же є».
**Причина:** назва в `.env`/документації і назва GitHub-секрета розходяться, а `${{ secrets.X }}` для неіснуючого секрета підставляє порожній рядок, не помилку. У цьому репо додатково: `deploy-workers.yml` мапить `CLOUDFLARE_API_TOKEN: ${{ secrets.CF_API_TOKEN }}` і `CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CF_ACCOUNT_ID }}` — три різні простори імен на один токен.
**Дій:** перед будь-яким воркфлоу, що ходить у зовнішній сервіс: `grep -h 'secrets\.' .github/workflows/*.yml | sort -u` і `gh secret list -R dreamcarua/barpi-brand-book`, і звіряй списки. Станом на 03.09.2026 у репо **немає жодного секрета** — `CF_API_TOKEN`, `CF_ZONE_ID`, `CF_ACCOUNT_ID` згадані у воркфлоу, але не встановлені.
**Seen:** 19.08.2026 (коментар у `deploy-workers.yml`), підтверджено 03.09.2026

### Заголовок `Origin` — не автентифікація
**Симптом:** дані виглядають «захищеними бо CORS», а `curl -H "Origin: ..."` віддає PII.
**Причина:** `Origin` тривіально підробляється будь-яким не-браузерним клієнтом. У `barpi-api` він приймався як доказ автентичності для читання будь-якої таблиці — 312 контрагентів, 260 з телефоном/email, плюс фінансові таблиці.
**Дій:** для персональних і фінансових ресурсів — тільки верифікований CF Access JWT (JWKS/RS256, перевірка `aud` і `exp`) або `X-API-Key`. `Origin` лишається лише для неперсональних агрегатів як defense-in-depth. Прапорець `ENFORCE_SENSITIVE` вмикається після того, як з'явиться роут за CF Access.
**Seen:** 12.06.2026 (P0-1)

### `ESCAPE` у SQL-рядку всередині JS template literal ламає auto-discover
**Симптом:** після деплою security-фіксу всі views віддають `[]`, дашборди порожні, у відповіді `x-resource-missing: v_dashboard_kpis`.
**Причина:** у воркері був `` `… name NOT LIKE '\_%' ESCAPE '\\'` `` всередині backtick-літерала. Undefined escape-послідовність `\_` у JS template literal зʼїдає бекслеш → SQL отримує `LIKE '_%'`, що матчить майже все → `NOT LIKE` відкидає всі таблиці.
**Роби:** не використовувати `ESCAPE` у SQL всередині JS-рядків. Замість `name NOT LIKE '\_%'` писати `substr(name, 1, 1) != '_'`. Після будь-якого деплою воркера перевіряти не тільки `/healthz`, а й реальну вибірку з view.
**Бачено:** 10.06.2026

### D1 падає на `UPDATE` з корельованим підзапитом через JSON1
**Симптом:** `UPDATE moysklad_processing_acts SET materials_sum_uah = (SELECT … FROM v_processing_act_cost WHERE act_ms_id = …)` → `code 7429: D1 DB exceeded its CPU time limit and was reset`.
**Причина:** `v_processing_act_cost` парсить `raw_json` через `json_each` для ~1900 актів, а корельований підзапит перезапускає це на кожному рядку.

**Бачено:** 10.06.2026
