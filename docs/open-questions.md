Заблоковано, доки не вирішить людина. Відповіли → пункт переїжджає в `docs/decisions.md`. У `docs/tasks.md` лишається один рядок-вказівник (розділ ⏸), повний текст живе тут.
Установка системи пам'яті 03.09.2026 виконувалась автономно, без інтерв'ю — усе нижче позначене `<?>` виведено з файлів репо, а не підтверджено власником.

## `<?>` Чи ставимо CF-секрети в репо, чи деплой назавжди лишається ручним
**Запитано:** 03.09.2026, Вадиму (не підтверджено)
**Варіанти:** A — поставити `CF_API_TOKEN`, `CF_ACCOUNT_ID`, `CF_ZONE_ID`, повернути push-тригер у `deploy-workers.yml`, закрити P0-1 і P1-1. B — лишити деплой через `wrangler` з Mac і прибрати мертві воркфлоу, щоб вони не створювали ілюзію автоматики.
**Рекомендація:** A. Без секретів `deploy-cf-headers.yml` фізично не може відпрацювати, а P0-1 (PII через Origin-spoof) лишається відкритим на живому воркері.
**Заблоковано доти:** security-заголовки, редеплой `barpi-api`, увімкнення `ENFORCE_SENSITIVE`.

## `<?>` Канал звітів у Telegram — куди саме слати
**Запитано:** 03.09.2026, Вадиму (не підтверджено)
**Варіанти:** A — GitHub Action `report-to-telegram.yml` з секретами `TG_BOT_TOKEN` і `TG_CHAT_ID` (стандарт набору memory-kit, той самий, що в `dreamcar-dashboard`). B — використати Edge Function `telegram-bot` у Supabase, яка вже задеплоєна, але живе в контурі `barpi-hq` під питанням. C — не мати каналу, звітувати у відповіді.
**Рекомендація:** A — один механізм на всі репозиторії групи; бот у Supabase розв'язує іншу задачу (команди від людей, а не звіти агента).
**Заблоковано доти:** воркфлоу не створено; значення секретів агент не бачить і не вигадує. Точні команди — у `docs/tasks.md`.

**Запитано:** 03.09.2026, Вадиму (не підтверджено)
**Варіанти:** A — визнати обидва закритими: авторизацію робить CF Access, дані — D1; прибрати згадки з `DEPLOY_NOTES.md` і README функції, код лишити в репо як історію. **Рекомендація:** A. `barpi-auth` дублює CF Access; Supabase-проєкт зник зі списку (P2-9), а дашборди вже читають з D1.
**Заблоковано доти:** не чіпати `barpi-auth/`, не видаляти `supabase/`, не переписувати `DEPLOY_NOTES.md`.
